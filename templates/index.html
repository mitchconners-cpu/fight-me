PROTOCOL SPECIFICATION :: ESCROW WAGERS

Decentralized state machine ensuring trustless escrow settlements via multi-sig cryptographic locking.

  • Phase 01 [Init]: Challenger broadcasts wager payload. System allocates unique hash identifier and target address.
  • Phase 02 [Fund]: Participants push exact satoshi amounts to designated escrow addresses.
  • Phase 03 [Execute]: Automated daemons listen for mempool confirmations, shifting state from PENDING_ACCEPTANCE to ACTIVE.

SYSTEM MANUAL :: WAGER GATEWAY API v1.1

CLI and HTTP interface specifications for automation scripts.

  • Database Kernel (`project.db`): SQLite3 relational store tracking table records for bets and chat_messages.
  • Webhook Daemons: POST /api/v1/escrow/deposit-webhook listening for inbound blockchain state changes.
